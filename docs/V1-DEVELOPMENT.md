# BrainAge Web 第一版开发规格

版本 1.1 · 2026-11-12 · 交付对象 sol

## 1. 目标与默认决策

实现中文响应式 Web，支持手机与电脑浏览器。核心流程为测评、结果解释、练习、历史回顾。面向一般成年用户，首版用于认知任务体验和个人表现记录。

本规格选定 React、TypeScript、Vite、免登录、本地保存、两个测评任务、空间记忆训练和文字引导正念。这些是根据资源约束作出的实现默认值。任务时长、阈值和难度均为工程与产品假设，尚未经心理测量验证。面向用户使用“任务表现”“空间记忆”“注意表现”等名称，避免把任务成绩直接解释为整体认知能力。

首版交付边界包括完整可运行网站、可复现安装与构建、必要测试及使用说明。脑龄模型、同龄常模、六维综合分、医疗筛查、账号同步、付费、社交排行、后台管理、小程序和自动部署列入后续版本。

## 2. 完成标准

- 用户可免登录完成说明、练习、状态记录、两个正式任务和结果查看。
- 用户可独立开始空间记忆训练与五分钟文字正念练习。
- 刷新后可读取已保存结果，删除全部数据后显示空状态。
- 被中断、计时异常、存储失败和部分完成都有明确反馈。
- 正式成绩由原始试次确定性计算，训练记录与测评记录可明确辨识。
- 手机触屏和电脑键盘均能完成主要流程。
- 任务完成后逐步点亮四轴任务表现雷达，支持部分完成、零分和质量异常状态，按第 18 节验收。

## 3. 页面与导航

采用 Hash 路由，确保静态托管和刷新可用。

| 路径 | 内容与交互 |
| --- | --- |
| / | 品牌、简短介绍、开始测评、开始练习、最近一次记录；首次访问为空状态 |
| /assessment/setup | 预计约 5–8 分钟、数据用途说明、状态输入、输入方式选择 |
| /assessment/run | 任务说明、练习、正式任务、任务间休息 |
| /results/:id | 科幻风格任务表现雷达、完成状态、质量提示、原始指标、保存状态、训练入口 |
| /training | 空间记忆和正念两个入口 |
| /training/memory | 分级练习与结束反馈 |
| /training/mindfulness | 五分钟引导与暂停、继续、结束 |
| /history | 按日期倒序的测评与训练记录，类型筛选、详情入口 |
| /about | 使用说明、研究来源、本地数据说明、删除全部记录 |

直接进入缺失结果显示“这条记录在当前浏览器中不可用”，并提供返回记录页。缺少活动会话时进入 run 路由应返回 setup。浏览器后退离开正式任务触发中断处理。

首页文案建议为“了解当下表现，建立专注练习习惯”。数据说明为“记录保存在当前浏览器。清理浏览器数据或更换设备后，记录可能无法访问。”

## 4. 测评流程

顺序固定为状态记录 → 空间记忆说明与练习 → 正式空间记忆 → 雷达阶段反馈与用户主动继续 → 注意任务说明与练习 → 正式注意任务 → 完整结果。阶段反馈位于 run 路由，正式任务呈现期间隐藏雷达。

状态字段均可跳过。昨晚睡眠时长输入 0–24 小时，步长 0.5；当前困倦采用 1–5 级明确文字选项；当前主观专注采用 1–5 级选项。自编问题只提供背景记录，不计算量表总分，不自动推断因果。

每项任务开始前选择触屏/鼠标或键盘，正式任务中固定输入方式。记忆键盘对应九宫格数字 1–9，注意任务使用空格。显示完整映射并先练习。输入类型与设备信息写入记录。

练习可重复，正式任务不给逐题对错反馈。用户可退出，已完成任务保存为部分完成结果。

## 5. 空间序列测评 memory-v1

### 任务与参数

三乘三九宫格依次点亮，用户按原顺序复现。该任务主要观察短时空间序列记忆，首版报告名称为“空间记忆任务表现”。

- 练习固定两条长度 2 的序列；全对后可进入正式任务，失败时展示解释与重试。
- 正式序列长度依次为 3、4、5、6，每个长度两题，共八题。
- 每题先显示 500 ms 准备屏；每个位置点亮 600 ms，随后熄灭 300 ms；最后一个位置熄灭后开放作答。
- 同一序列位置互不重复。同一会话八条序列互不相同。
- 作答按次数记录；达到序列长度自动提交，开放作答 15 秒仍未完成则提交已有输入并标记超时。
- 作答阶段可显示已输入数量与短暂按下反馈；序列呈现阶段忽略输入。
- 每题后中性间隔 800 ms。固定完成八题，避免自适应路径影响历史对比。

### 计分

- 完全正确题数 0–8；完全正确率 = 完全正确题数 / 8。
- 位置正确率 = 对应位置答对的数量 / 所有呈现位置数量；未输入的位置计错。八题总呈现位置为 36。
- 最高成功长度 = 至少一题完全正确的最大长度；全错时显示“本次尚未完整复现序列”。
- 超时正常计入测评；技术中断试次按第 8 节处理。
- 结果显示正确题数和最高成功长度。详细页显示位置正确率与超时次数。
- 部分任务显示已答试次，整体指标使用 null，避免按剩余试次数重新归一成完整成绩。

## 6. 注意目标识别测评 attention-v1

### 任务与参数

屏幕中央呈现圆形或三角形。圆形出现时点击固定底部响应按钮或按空格，三角形出现时等待。形状区与响应区位置固定，避免手指遮住刺激。

- 练习 10 个试次，圆形 6 次、三角形 4 次，逐题解释；至少 8 次判断正确方可进入正式任务，允许重练。
- 正式任务 100 个试次，圆形 70 次、三角形 30 次。
- 每 20 个试次含 14 个圆形和 6 个三角形，块内随机排列；记录实际顺序。
- 每试次刺激显示 600 ms，之后为空白。整个响应窗口为刺激起点至 1000 ms。
- 下一试次起点间隔从 1400、1600、1800 ms 选择，全任务三种间隔分别为 34、33、33 次，随机打乱，总计划时长约 160 秒。
- 每个响应窗口只接收第一次有效按下，后续按下计为重复事件；窗口外响应独立记录，不归到下一题。
- 按键使用 keydown，忽略 event.repeat；指针使用 pointerdown。确保相同物理动作只计一次。

### 计分与反馈

- 圆形且在 [100, 1000) ms 内响应为命中；无响应为遗漏。
- 圆形在 [0, 100) ms 响应标记过早，计入目标未有效命中，单独统计。
- 三角形在 [0, 1000) ms 任何首次响应均为误按；无响应为正确抑制。
- 命中率 = 有效命中数 / 70；误按率 = 误按数 / 30。
- 反应时间中位数只计算有效命中；反应波动使用同一集合的四分位距 IQR。
- 四分位数使用排序后索引 (n−1)p 的线性插值，保证实现与测试一致。
- 有效命中少于 10 个，反应时间和 IQR 返回 null，显示“有效反应不足”。
- 展示命中率、遗漏数、误按数、反应时间。IQR 放详情并解释为本次反应速度的离散程度。
- 完整任务的零命中是可报告的低表现；技术质量与表现高低分别记录。
- 如窗口内过早响应占所有窗口内首次响应超过 20%，或窗口外事件超过 20 次，标记“作答方式需要核对”，保留原始结果并取消历史比较资格。阈值是产品规则，尚未经学术验证。

## 7. 训练

### 空间记忆训练

沿用九宫格呈现组件，独立 taskVersion 为 memory-training-v1。每次最多 12 题，初始长度 3，范围 2–8。连续两题完全正确升一级并清空连续计数；任何一题错误或超时降一级并清空连续计数；达到上下限保持边界。

每题提供反馈，可回放正确序列一次，回放不产生额外成绩。第 12 题结束显示完成数、正确数、最高练习长度；用户可随时结束并保存部分训练。该成绩仅进入训练记录。

### 文字正念练习

五分钟，分五段各一分钟。内容依次为安稳坐好与自然呼吸、留意呼吸感受、发现走神、温和把注意带回、觉察身体并结束。允许自然呼吸和保持睁眼，避免屏息及强制呼吸节律。

提供可见倒计时、当前引导、暂停/继续/结束。切后台自动暂停，返回后由用户继续。实际练习时间只累计前台运行时间。满 300 秒标记完成，提前结束记录实际秒数。文案说明这是注意觉察练习，具体五分钟版本的效果尚未独立验证。

## 8. 计时、状态机与中断

核心状态为 idle、instructions、practice、ready、presenting、responding、feedback、completed、interrupted。状态转移通过 reducer 或小型显式状态机管理。

- 时间间隔使用 performance.now()；日历时间使用 ISO 时间戳。二者用途独立。
- 使用 requestAnimationFrame 安排刺激呈现，记录请求呈现时间与帧回调时刻。该时刻是软件呈现估计，不能声称为硬件实际显屏时间。
- 计时用绝对截止时间推进，避免 setInterval 累积漂移；渲染状态变化不能重建一组计时器。
- 单一控制器管理监听、帧回调和计时器；退出、卸载、中断后统一清理。React StrictMode 下禁止双重启动。
- 正式任务遇 document.hidden、窗口失焦、方向改变或导致布局变化的 resize，立即进入 interrupted，冻结输入，当前试次作废。
- 显示“测试被打断”，提供重新开始当前任务或结束测评。重新开始使用新 attemptId 和新序列，已完成的另一任务保留。次数不受限，保留中断摘要。
- 活动任务跨刷新恢复时标记中断，要求重做当前任务；已完成任务可继续沿用。
- 记录帧间隔及刺激起点延误摘要。出现超过 250 ms 的帧间隙或起点延误，标记技术质量问题，该任务结果保留但取消历史比较资格，并提供重测。这是可调整的工程阈值。
- 正式任务禁止手动暂停后接着计分。正念、任务说明和任务间休息可以暂停。
- 计时敏感阶段避免同步存储和网络请求。试次数据驻留内存，任务完成或中断后一次保存。

## 9. 数据契约

全部对象包含 schemaVersion: 1。使用 crypto.randomUUID() 生成 sessionId、attemptId。每个任务包含 taskId、taskVersion 和 scoringVersion。正式参数作为不可变配置集中管理，修改协议时递增 taskVersion。

| 实体 | 必需字段 |
| --- | --- |
| AssessmentSession | id, schemaVersion, startedAt, finishedAt/null, status(inProgress/completed/partial/interrupted), context, taskAttempts, selectedAttemptIds |
| Context | sleepHours/null, sleepiness/null, subjectiveFocus/null, deviceClass, viewport, browserFamily, inputModeByTask |
| TaskAttempt | id, taskId, taskVersion, scoringVersion, startedAt, endedAt/null, status, inputMode, trials, qualityFlags, timingSummary, metrics |
| MemoryTrial | index, sequence, response, presentationTiming, responseTimesMs, timedOut, valid, invalidReason/null |
| AttentionTrial | index, stimulus, plannedOnsetOffsetMs, onsetOffsetMs, firstResponseMs/null, repeatedResponsesMs, valid, invalidReason/null |
| TrainingSession | id, schemaVersion, trainingType, taskVersion, startedAt, endedAt, status, activeDurationMs, trials, summary |
| Preferences | schemaVersion, preferredInput, reducedMotionPreference |

时间数组以本次 attempt 起点为相对零点。注意任务窗口外响应保存在 attempt.outOfWindowResponsesMs。metrics 从原始数据计算，null 表示无法计算，禁止用 0 代替缺失。持久化时保存原始数据与指标，读取时校验结构及版本。

practice 数据可在当前会话内用于教学，排除正式指标和历史比较。累计尝试保留中断摘要，selectedAttemptIds 仅指向用户最终完成的当前有效尝试。

## 10. 本地保存与历史比较

使用 localStorage，封装 storage adapter，键前缀 brainage.v1。每个会话单独一个键，通过前缀扫描构建历史列表，避免主索引与会话不一致。首次启动检查存储可写性；失败时启用内存模式并持续提示“本次记录尚未保存，离开页面后可能丢失”。

每完成一个任务保存会话，训练结束保存训练记录。相同 id 覆盖写入，重复提交不会新增记录。JSON 解析失败时跳过损坏项并提示，避免自动覆盖原始内容；未知 schemaVersion 提示版本不兼容。

存储配额不足时保留内存结果，显示失败和重试；数据删除由用户明确操作。删除全部记录需要确认，删除范围限定 brainage 前缀，禁止 localStorage.clear()。监听 storage 事件更新其他标签页的历史；活动会话发现数据已清除时中止，避免旧会话再次写入。

历史比较只匹配相同 taskVersion、scoringVersion、deviceClass、browserFamily、inputMode 且质量合格的完整任务。以最近一次匹配记录为对比，找不到时显示“暂无可比较记录”。正确率变化使用百分点，反应时间变化使用毫秒，同时展示正确率和误按情况。避免仅根据速度变快判断改善。

首版历史提供列表及最多最近十次的简单趋势。每点可查看日期和原始值，只有一次时显示单点与说明。图表需有等价文本表格。页面说明“重复练习、设备和当天状态会影响表现”。

## 11. 界面与可访问性

中文界面，清晰、安静、留白充分。整体沿用用户选择的“自然专注”方向；阶段反馈和结果页采用第 18 节的深色科幻视觉。字体采用本地系统中文字体，拉丁字符可用 Inter 并提供系统回退。组件样式采用 CSS Modules 与少量 CSS variables。

最小视口 360px 宽，覆盖 390px 手机、768px 平板、1440px 桌面。按钮触控区域至少 44px，键盘焦点可见，说明文字可缩放。刺激通过形状及位置区分，颜色作为辅助。

任务运行时减少导航和装饰动画，保留退出按钮。记忆序列和注意刺激使用固定尺寸和稳定布局，资源预加载后再开始；任务区域加载失败时阻止开始并说明。

尊重 prefers-reduced-motion。正念引导通过静态文字即可完成。说明、按钮、结果与历史支持辅助技术；视觉计时任务的可访问性限制需在说明中明确，避免未经验证的辅助模式与标准成绩混合。

## 12. 技术结构

采用 React + TypeScript strict + Vite，React Router HashRouter，CSS Modules。当前仓库仅有目录骨架，Web 放在 apps/web。测评纯逻辑放在 apps/web/src/domain，限制依赖为 TypeScript 标准能力，方便未来抽取给小程序。

建议目录包含 app（路由与布局）、pages、components、domain/tasks、domain/scoring、domain/types、platform/timing、platform/storage、features/assessment、features/training、styles。根据实际规模合并文件，避免空层级和通用插件系统。

纯函数覆盖序列生成、计分、训练难度和历史匹配；随机源可注入，实际生成序列写入数据。UI、计时及存储通过明确接口调用核心逻辑。

开发时确认兼容依赖并提交 lockfile，README 写明 Node 版本和命令。2026-11-12 检查到本机 Node 为 20.12.2，而当前 Vite 文档要求 20.19+ 或 22.12+；实施前选用满足所选 Vite 要求的受支持 Node，并核验安装和构建环境。[Vite 文档](https://vite.dev/guide/)

提供 npm run dev、build、preview、typecheck、lint、test 和 test:e2e。单元测试用 Vitest，关键浏览器流程用 Playwright。测试可以注入时钟和固定序列，正式构建必须使用正式协议参数。

## 17. Docker 开发与云端部署

增加可移植的 Docker 环境作为首版交付内容。开发运行 Node 与 Vite，生产采用多阶段构建生成静态资源，并交给 Nginx 提供 HTTP 服务。[Docker 多阶段构建](https://docs.docker.com/build/building/multi-stage/) · [Vite 静态部署](https://vite.dev/guide/static-deploy)

### 文件与运行约定

- apps/web/Dockerfile 定义 dev、build、production 阶段。开发和构建使用同一固定版本的受支持 Node 官方镜像，生产使用固定版本 Nginx 官方镜像。实施时核对版本并记录，采用 npm ci 和 lockfile 安装。
- 仓库根目录 .dockerignore 排除 .git、node_modules、dist、日志和本地环境文件。
- 根目录 compose.dev.yaml 配置开发服务 web，使用仓库根作为构建上下文，绑定 apps/web 源码到工作目录，并以独立命名卷挂载容器 node_modules，避免 Windows 与 Linux 依赖混用。启动时 npm ci，使 lockfile 变化能够生效。
- 开发 Vite 监听 0.0.0.0:5173，默认端口映射 127.0.0.1:5173:5173。需要手机局域网访问时提供明确的端口映射覆盖示例。
- Windows Docker Desktop 使用 Linux 容器。文件监听失效时提供可选 polling 开关，默认保持普通监听。
- 根目录 compose.prod.yaml 配置生产服务 web，构建 production 阶段，默认映射 127.0.0.1:8080:80，restart 为 unless-stopped，配置可执行的健康检查。生产服务通过宿主机 HTTPS 反向代理或云负载均衡访问。
- apps/web/nginx.conf 配置静态资源、正确 MIME、gzip 和 /healthz。index.html 使用重新验证缓存策略，带哈希资源采用长期 immutable 缓存，缺失资源返回 404。现有 Hash 路由直接由 index.html 承载。

### README 必须提供的命令

以下是实现后的验收命令，当前文档阶段尚未创建配置文件。

```sh
# 开发
docker compose -f compose.dev.yaml up --build

# 构建并启动生产版本
docker compose -f compose.prod.yaml up -d --build

# 状态与日志
docker compose -f compose.prod.yaml ps
docker compose -f compose.prod.yaml logs --tail=100 web

# 停止生产服务
docker compose -f compose.prod.yaml down
```

完整使用 Docker 开发时，宿主机只需 Docker 与 Compose，Node 工具链由容器提供。第 12 节的宿主机 Node 升级适用于直接在宿主机运行 npm 的路径。

### 部署与数据约定

生产镜像包含编译后的静态资源。容器启动后由 Nginx 提供服务，Vite preview 用于本地预览。未来 VITE_ 配置随构建注入，浏览器可读取这些值，私密凭证应放在未来服务端的运行配置中。

当前业务数据保存在用户浏览器 localStorage。部署、升级与容器重启不会将记录同步到云端；同一浏览器通过相同 origin 访问时可继续读取记录。域名、协议或端口改变会形成不同 origin，需要在正式使用前确定稳定 HTTPS 域名。

README 说明服务器需要 Docker Compose、可用镜像源、匹配的 CPU 架构及 HTTPS 入口。默认流程在目标服务器构建；如由开发电脑构建镜像，需匹配服务器 linux/amd64 或 linux/arm64。发布与回滚使用可追溯版本标签，记录前一个可用镜像版本。实际域名、证书及云端发布在部署任务中配置。

### 容器验收

验证开发热更新、容器内 typecheck/test/build、生产镜像构建、健康检查、静态资源加载、Hash 路由刷新和容器重启。清洁构建必须脱离宿主机 node_modules 成功。检查生产配置仅提供预期 HTTP 端口。若执行环境无 Docker，交付中明确记录容器运行未验证，并完成可执行的配置与应用检查。

## 18. 科幻结果页与逐步点亮雷达

### 可视化参考入口

打开 [结果页交互参考](radar-reference.html)，可在浏览器直接查看桌面和手机布局，切换“未开始”“完成空间记忆”“全部完成”“建议重测”，点击指标查看解释。所有成绩为示例。主按钮演示阶段切换与原始结果展开。

该文件为独立设计参考，正式实现需使用本文的数据契约与任务状态。参考覆盖配色、布局、雷达几何、部分完成状态及详情交互；正式产品还需完成第 18 节定义的单次点亮动画、存储反馈和真实数据接入。参考已检查脚本语法，浏览器视觉和真机体验待实现阶段验证。

### 设计决策

用户希望每完成一项测评，就点亮相应维度。首版采用四轴“任务表现雷达”，两项测评各贡献两个可直接计算的指标。四轴表达本次任务的不同观察角度，指标间存在相关性。首版页面明确显示“2 项任务 · 4 个表现指标”，解释文字为“各轴为本次任务的正确比例，指标可能相关；结合下方原始结果阅读”。

采用四轴是首版基于现有任务作出的产品决策。空间记忆与注意任务各点亮一组轴。未来新增经过明确设计的任务后，可增加独立指标，届时递增 radarVersion 并重新评估历史展示。避免把尚未实现的能力展示为用户低分或零分。

### 轴定义与分数

雷达版本 radar-v1。起点位于正上方，顺时针排列如下，各轴固定范围 0–100，网格刻度为 25、50、75、100。

| 轴 ID | 用户标签 | 数据来源 | 计算 |
| --- | --- | --- | --- |
| sequenceAccuracy | 序列复现 | memory-v1 完全正确率 | 完全正确题数 / 8 × 100 |
| positionAccuracy | 位置记忆 | memory-v1 位置正确率 | 对应位置正确数 / 36 × 100 |
| targetHitRate | 目标识别 | attention-v1 命中率 | 有效命中数 / 70 × 100 |
| correctRejectionRate | 干扰抑制 | attention-v1 正确抑制比例 | (30 − 误按数) / 30 × 100 |

轴标签展开说明分别为“完整复现序列的比例”“按正确位置复现的比例”“及时响应目标的比例”“遇到非目标时成功等待的比例”。显示一位小数，整数可省略小数位，几何位置使用未四舍五入值。示例 6/8 显示 75，65/70 显示 92.9，误按 2 次对应 93.3。

显示数值旁附百分号或统一说明“正确比例 %”。此处的 0–100 是原始比例的百分制表达。反应时间和 IQR 保留毫秒原始指标，放在雷达下方；睡眠、困倦与自报专注保留状态记录。首版不计算雷达面积总分、平均能力分或脑龄。

### 点亮与空值状态

每轴派生为 pending、ready 或 review。只有完整任务且没有第 6、8 节质量标记时为 ready；未完成或中断任务为 pending；完整但出现作答或计时质量问题时为 review。有效命中不足十次仅使反应时间指标缺失，四轴仍依据完整任务的比例计算。

- pending 使用低亮度中性轴线与“待完成”，value 为 null。
- ready 点亮轴标题与端点，显示真实分数。零分端点位于中心，同时轴标题显示“0% · 已完成”，让用户与待完成状态区分。
- review 显示琥珀色状态符号和“建议重测”，雷达绘制值为 null；下方详情仍显示原始结果及具体原因。
- 仅部分轴 ready 时绘制独立径向分数线和端点。四轴全部 ready 后连接闭合多边形，并添加低透明度填充。
- 存储失败与测量质量分别显示；内存中的完整合格结果仍可点亮，同时显示“尚未保存”。

首项任务完成后在任务间反馈区展示雷达，点亮两条记忆轴，标题显示“空间记忆已完成”，主按钮为“继续注意测评”。第二项完成后展示其余两轴与完整结果。任务完成数以任务 status 计算，指标点亮数以 ready 计算，分别标为“完成 1/2 项测评”“已点亮 2/4 个指标”。

重做当前任务时先移除该任务原来的雷达派生结果，保留另一任务数据。历史页面打开时直接展示最终状态。训练结束展示自身训练结果，保持正式测评雷达的数据来源一致。

### 视觉与动效

结果区域使用深墨绿色背景 #101D1B、面板 #172824、正文 #E8F4EF、次要文字 #A8C0B5、主色 #77E1BA、网格 #36534A、质量提示 #EBC27B。这些颜色作为候选设计 token，实现时检查实际对比度并调整。

视觉重点是中部雷达、已完成状态和原始结果。采用细线网格、轻微端点光晕、紧凑的数据标签。保留自然专注风格的圆角与中文可读性，结果页可以深色呈现，正式测评刺激样式保持协议一致。

仅在新任务完成时执行一次 600–900 ms 的轴点亮与端点移动。完成状态即时可读，按钮即时可操作，动画不阻塞继续。避免从 0 递增滚动分数字样，避免循环扫描、闪烁、自动音效。prefers-reduced-motion 开启时直接显示终态。

结果页顺序为完成状态 → 雷达与状态图例 → 可点击指标详情 → 原始任务结果 → 状态记录 → 训练/返回入口。标题可用“本次表现已记录”，存储失败时改用“本次测评已完成”，并显示保存错误。

手机端雷达宽度随容器变化，在 360px 视口仍保留完整标签与触控入口；桌面端可将指标详情放在雷达右侧。轴标签可点击、键盘可操作，展开分子/分母、解释和来源任务。提供等价数据表和简短可访问描述，颜色之外配合文字状态。

### 实现接口与历史

派生函数 buildRadar(session) 返回 radarVersion、axes、completedTaskCount、readyAxisCount。每轴包含 id、label、sourceTaskId、sourceAttemptId/null、status、value/null、numerator/null、denominator、reason/null。函数从 selectedAttemptIds 指定的原始任务指标计算，不另行存储一份可变分数。

使用可测试的响应式绘图组件，所有计算与图形渲染分开。缺失指标不参加几何计算；生成坐标前检查 finite、范围与 status。历史结果按原 taskVersion/scoringVersion 解释，不以新的参数重算旧版本。未知协议给出明确的兼容提示。

首版雷达展示当前结果，历史比较继续采用第 10 节的同条件列表与趋势。相邻两次差异仍用百分点表达。雷达动画完成次数仅属界面状态，禁止动画触发再次保存或重算成绩。
